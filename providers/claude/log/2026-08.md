## 2026-08-02 — readiness-argv added: `claude auth status` (trigger: Step-0 Part B — honest readiness; 2.1.220)

Added `readiness-argv: ["claude", "auth", "status"]` so Step-0 readiness proves
authentication, not just CLI presence. Previously readiness fell back to `claude
--version`, which succeeds while logged out.

**Auth-gating verified live (2.1.220):**
- Logged in: `claude auth status` → `{"loggedIn": true, "authMethod": "claude.ai", …}`, exit 0.
- Isolated logged-out (`env -u ANTHROPIC_API_KEY HOME=$(mktemp -d)`, real creds untouched):
  `{"loggedIn": false, "authMethod": "none"}`, exit 1.

Cheap, non-mutating. Output carries account identity metadata (email/org), not a
credential/token — acceptable for a local readiness probe. Real user auth now yields
`ready: claude` instead of `available (auth unverified): claude`.
