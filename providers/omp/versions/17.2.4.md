## Cross-CLI comparison — omp cells

| Property | omp |
| --- | --- |
| Prompt argument | **positional / trailing message**; `-p`/`--print` selects non-interactive mode and is REQUIRED for headless dispatch. Flags parse in any position — no `-p`-eats-next-arg trap, no `-p`=password trap. |
| `< /dev/null` needed | **Recommended.** In `-p` mode a supplied message is processed and omp exits; dispatches ran clean with `< /dev/null`. Kept for parity/safety. |
| Sandbox | **None.** Built-in tools (write/edit/bash/read) run with the omp process's permissions. `--auto-approve` runs every tool ungated headlessly (**verified**: `write` + `bash` executed non-interactively, created a file and ran a shell command). Treat every dispatch as full-host capability; clean-tree-before + diff-after per `../../../core/safety-doctrine.md`. |
| Permission flags | `--approval-mode always-ask\|write\|yolo`; `--auto-approve` skips all approval prompts (**mandatory for headless**). `--add-dir <dir>` widens the workspace beyond cwd; `--cwd <dir>` sets the start directory; `--profile` isolates auth/sessions/caches. |
| Exit codes | `0` success; missing/absent-backend model or missing API key → `1` (the dispatch throws "No API key found for <provider>"). |
| Model validation | Fuzzy `--model` resolves against the `omp models` catalog; an unauthed/absent backend fails only at dispatch (exit 1), not locally. Resolve ids from `omp models`. |
| Reasoning-effort control | `--thinking off\|minimal\|low\|medium\|high\|xhigh\|max\|auto`; per-model available levels are shown in `omp models`. |
| Output contract | `--mode text` → clean final assistant message on stdout (progress spinner on stderr). `--mode json` → full event stream (`session`, `message_*`, `tool_execution_*`, terminal `agent_end` with `isTerminal:true`). Incremental events make **log-age** stall detection work. |
| Auth | **Multi-account**: `anthropic` / `openai-codex` / `google-antigravity` / `opencode-go` / `xai-oauth`, each via its own subscription / OAuth / API key. `omp models` lists only authed backends but exits `0` even when none are authed. |
| Model surface | `omp models` — catalog grouped by backend (context / max-out / thinking levels / images). **No exit-code auth gate.** |
| Changelog | Oh My Pi (`omp`) — read on every version bump before probing. |

## Sessions — id recovered from print output

omp records the session id in `-p --mode json` output: the **first** stream line is
`{"type":"session","version":3,"id":"<uuid>",...}`. `session-source: exec-output` reflects
this — the controller parses the id from the print stream. Sessions are persisted as
`<ISO-ts>_<uuid>.jsonl` under `--session-dir` (or the default session store).

Resume by id (full id or a prefix): `omp -p -r <id> "<continuation>"`.

- **Resume verified**: after `omp -p -r <8-char-prefix>` the model recalled a value set on the
  previous turn (`PONG`) — full memory continuity.
- **`-c` / `--continue`** resumes the most recent session in the store.
- **No fork-session flag.** omp imports foreign histories via `--from-claude` / `--from-codex`
  but exposes no in-family fork; `fork-flag` is omitted. Re-review in a branch by dispatching a
  fresh session against the same tree.

### Resume — a kill is a checkpoint, not a restart

| CLI | Resume |
| --- | --- |
| omp | `omp -p -r <id>` (by id or prefix) / `--continue` for the most recent in the store |

Working-tree progress survives a kill (tools write as they go) — `git diff` before resuming.

## Report — captured-output

The deliverable answer is the **last assistant message** in the terminal `agent_end` event
(`isTerminal:true`); in `--mode text` it is the clean stdout. `report-transport:
captured-output`. Instruct the agent to end its final message with the four-status line; the
controller extracts the last assistant message (never the echoed user turn) and reads that
STATUS.

## Verified behavior

- **Tool execution is headless under `--auto-approve`**: a dispatch created `pong.txt` via the
  `write` tool and confirmed it via the `bash` tool (`tool_execution_start/end` events, exit 0),
  with no interactive approval. Every tool runs with the omp process's full permissions —
  there is no sandbox.
- **`-p`/`--print` is mandatory** for headless dispatch; without it omp launches the TUI.
- **Session id via exec-output**: parsed from the first `type:session` line of `--mode json`;
  resume by id-prefix restored context.
- **Two output modes**: `--mode text` = clean final message; `--mode json` = event stream that
  feeds log-age liveness. Dispatch in json to get both the session id and the streaming log.
- **No cheap auth-probe subcommand**: `omp models` exits `0` even unauthenticated
  ("No models available. Set API keys in environment variables."), so it cannot serve as an
  exit-code readiness gate. `readiness-argv` is omitted → preflight defaults to `version-argv`
  (local only) → Step-0 reports **`available (auth unverified): omp`**. Auth reachability
  surfaces as a channel failure on the first real dispatch, handled by the standard fallback
  rules.
- **Multi-account auth is not binary**: different backends carry different credentials; a
  route can be ready for one model and unauth for another. The channel-failure fallback is
  per-dispatch, per-model.

## Canonical dispatch template

```bash
cd <repo> && omp -p --mode json --auto-approve --no-title \
  --session-dir <per-task-dir> --model <model> "<prompt>" < /dev/null
```

Run inside the detached self-reaping wrapper (`../../../core/liveness.md`); keep stdout in the
per-task log (json events → log-age stall detection); parse the session id from the first
`type:session` line and record it in the ledger for resume; the final answer is the last
assistant message in the terminal `agent_end` event.
